# V20-C1 与 V20-C2 预注册确认实验：完整审计报告

**鉴定日期：2026-09-28**  
**项目：ProbeRoute 数据局部化联邦检索**  
**报告性质：实验审计版，不是论文终稿。**

## 1. 摘要与审计结论

本报告记录两次连续、独立的预注册确认实验：C1（首次确认）与 C2（独立复现）。研究对象为数据不离开客户端的多跳检索：协调端先从静态候选中取 8 个客户端；每个候选返回 18 维 float32 局部检索探针；M2 Logistic ProbeRoute 使用 18 个传输探针特征和 1 个协调端静态分数（共 19 个模型输入维度）选择 3 个客户端；每个选中客户端本地检索深度为 10、传回 5 篇文本，协调端以原始稠密分数合并 Top-10，取 Top-5 构造冻结 Reader 输入。

两次确认均支持以下受限结论：在 3 客户端、15 篇文本的固定下行文档预算下，M2 相对于静态 Top-3（B0）稳定提高 Top-5 完整证据恢复率；C2 中三个数据集的提升为 `+5.2` 至 `+7.8` 个百分点，所有对应的 Holm 校正 p 值均为 `0.0072`。C2 的双 Reader 联合 F1 也均显著高于 B0。相对于 8 客户端、40 篇文本的高成本参照 B4a，M2 的上下文完整性与联合 F1 基本持平或接近。

C2 新增实际文本 payload 审计。在 `UTF-8(title + "\\n" + text)` 文档序列化下，M2 加上固定 576 bytes 探针和显式协议头诊断值后，相对 B4a 的总诊断 payload 降低 `58.8%--60.7%`。该结果支持“接近高预算检索效用而显著减少通信 payload”的表述；但它不等价于已在真实网络 RPC 中测得端到端带宽或延迟。

## 2. 研究问题与受检验主张

**RQ1：** 在固定的 3 客户端/15 文档预算下，局部检索探针驱动的 M2 是否比静态路由恢复更多完整多跳证据？  
**RQ2：** 上游完整证据增益能否在冻结 Reader 的回答与支持证据联合 F1 上体现？  
**RQ3：** M2 能否以明显低于全候选高成本检索的通信 payload 获得近似的检索与下游效果？  
**RQ4：** C1 的结论能否在从未使用过、与所有历史集合双重去重的 C2 查询上复现？

本实验不检验、也不声称：M2 直接以 Reader reward 训练；M2 显式学习客户端间集合互补性；或本工作优于所有联邦搜索、RAG 路由方法。M2 是使用“客户端是否含支持文档”监督标签训练的独立客户端打分器，随后选 Top-3。

## 3. 冻结系统与比较对象

### 3.1 固定流水线

| 环节 | 冻结设置 |
|---|---|
| 静态候选 | 每查询 Top-8 客户端 |
| 探针 | 每候选 18 个 float32 标量；M2 模型还使用 1 个协调端静态分数 |
| M2 | 标准化、class-balanced Logistic Regression；按独立得分选择 Top-3 |
| 本地检索 | 每选中客户端 local depth = 10 |
| 文档传输 | 每客户端 5 篇，合计 15 篇；B4a 为 8 客户端、40 篇 |
| 合并/Reader 上下文 | 原始稠密分数合并 Top-10，取 Top-5 |
| Reader | FLAN-T5-Large `0613663d...`；UnifiedQA-v2-T5-Large `1d3b8e...` |
| 推理 | greedy decoding，最多 32 新 token，最大输入 1024 token，4,000 字符上限 |

Reader 在盲态阶段只收到问题和冻结上下文；没有调用测试标签、答案或支持事实。M2 也不是 Reader reward 优化器。

### 3.2 基线

| 方法 | 含义 | 客户端/文档预算 |
|---|---|---|
| B0 | 协调端静态分数 Top-3 | 3 / 15 |
| B1 | 固定 20 个随机种子（0--19）的随机 Top-3 | 3 / 15 |
| B3 | RAGRoute-style 浅层 MLP：query BGE、source centroid、source ID | 3 / 15 |
| B6 | 稠密 query--source centroid 路由 | 3 / 15 |
| M2 | 18 维局部探针 + 1 维静态分数的 Logistic ProbeRoute | 3 / 15 |
| B4a | 所有 8 个候选客户端的高成本参照 | 8 / 40 |

不可用的 B2p 未被替代或伪造结果。主比较为 M2 对 B0/B3/B6；B4a 是成本--性能前沿参照，而非同预算显著性主张。

## 4. 数据、独立性与盲态流程

数据集为 HotpotQA、2WikiMultiHopQA 和 MuSiQue。C1 与 C2 各数据集均有 500 个查询，每轮共 1,500 个查询、37,500 个 `方法 × 查询` 路由上下文单元，以及每个 Reader 37,500 条预测。

C2 从剩余、从未使用的公开训练池重新抽取，并排除 V17、R5、C1 和全部开发查询。C2 在查询 ID 及规范化问题文本 hash 两个层面与历史集合、特别是 C1 进行去重；其预注册清单记录为 `c2_fresh_split_manifest.json` 和 `c2_zero_overlap_audit.json`。目录中沿用的 `*_c1_blind_n500.jsonl` 是脚本兼容性文件名，不表示 C1 与 C2 使用同一查询。

每一轮均遵循：

1. 冻结划分、方法、Reader、预算、统计程序及输入工件。
2. 标签封存状态下生成各数据集 Probe packet。
3. 物化 B0/B1/B3/B6/M2/B4a 路由、合并文档及 Top-5 Reader 上下文。
4. 在两张 GPU 上完成双 Reader 无评分预测。
5. 对 37,500 路由上下文与两份 37,500 预测做完整性、唯一性、无标签字段及 SHA-256 核验。
6. 仅在收到明确人工指令后写入解封记录，读取公开训练源标签并计算指标。

- **脚本时点披露：** C2 的解封后评估适配器在解封后创建，用于将 C1 已冻结的 130 行评估逻辑从 `c1_label_unseal_record.json` 绑定到 C2 同名记录，并相应修改输出状态名称；没有修改指标、比较、bootstrap、随机化检验或超参数。该适配器提交为 `f4d4c28`。C2 字节审计的计算契约（576-byte probe、文档 UTF-8 payload、协议字段单列）在预注册中已写明；其可执行脚本在解封后实现且不读取标签，提交为 `3a2eb1a` 与 `eb5ef85`。因此，C2 的效应量不受这两个脚本改动影响，但最严格的未来确认应在解封前同时冻结所有阶段命名适配器与审计实现。

这些异常及恢复不应被隐去；审计结论建立在隔离失败部分输出、恢复后从头运行、再冻结全部可用工件的基础上。

## 6. 指标与统计程序

上游链条指标依次为：客户端集合完整性 `Complete@3`、本地 Top-10 完整性、15 文档传输完整性、全局 Top-10 完整性、Reader Top-5 上下文完整性（主上游指标）。下游采用答案 F1、支持证据 F1 和联合 F1（主下游指标）。完整性指同一查询的所有金标准支持文档是否都在对应集合中。

M2 对 B0/B3/B6 的主比较在每个数据集、Reader 和主指标上采用查询配对差值；使用 5,000 次 bootstrap 置信区间与 5,000 次符号随机化检验，并对 36 个计划比较进行 Holm 校正。表中百分点（pp）为绝对差值。由于上游上下文不依赖 Reader，同一数据集的完整性数值在两 Reader 列相同，但仍按预定义比较单元报告。

## 9. C2 字节级通信审计

文档 payload 使用本地 SQLite 中每篇实际传输文档的 `UTF-8(title + newline + text)` 字节长度。M2 的固定探针为 `8 × 18 × 4 = 576 bytes/query`。另报告一个透明的协议头诊断：以 JSON 序列化 `dataset + query_id + 8 个 client ID`，均值约 91--109 bytes；它只用于显示小型元数据量级，**不是**未部署 RPC 的 wire-level 宣称。

| 数据集 | M2 文档 payload | M2 探针 + 头部诊断 | M2 诊断总量 | B4a 文档 payload | M2 相对 B4a 降幅 |
|---|---:|---:|---:|---:|---:|
| HotpotQA | 7,561 B | 576 + 95 B | 8,232 B | 20,762 B | 60.4% |
| 2Wiki | 7,337 B | 576 + 109 B | 8,022 B | 20,436 B | 60.7% |
| MuSiQue | 8,290 B | 576 + 91 B | 8,956 B | 21,728 B | 58.8% |

文档数层面，M2 为 15 篇、B4a 为 40 篇，即 M2 是 B4a 文档数的 37.5%。字节审计进一步说明，即使纳入 M2 探针和小型头部诊断，其优势没有消失。C1 未执行对应的字节级审计，因此本报告不将 C2 的实测百分比外推为 C1 的实测字节结论。

## 10. 综合解释、有效性边界与后续工作

1. **被支持的结论。** 两个独立确认集均显示，M2 的局部检索状态探针比静态 Top-3 更善于选择包含完整多跳证据的客户端；C2 在两个冻结 Reader 上将该增益一致传递到联合 F1。
2. **成本--效用前沿。** M2 在 15 篇文本条件下逼近或匹配 B4a 的 40 篇文本效果；C2 直接观测到约 59%--61% 的诊断总 payload 降低。应使用“在该冻结模拟协议下的 payload 审计”而非“真实网络带宽/延迟降低”描述。
3. **不能过度归因。** M2 训练标签来自支持文档可用性，不能称为 Reader-aware 强化学习或学习集合互补性的策略。B3 仅为 RAGRoute-style 可运行近似，而非声称复现原论文的全部系统。
4. **统计边界。** 主显著性结论仅针对 M2 对 B0/B3/B6 的预定义比较；B4a 的接近性主要用于成本--性能解释，未被包装为同预算优效检验。
5. **外部有效性。** 三个多跳 QA 数据集、两个冻结 Reader 和 1,500 查询/轮提供了跨数据集、跨 Reader 证据，但仍不覆盖动态客户端、真实网络、其他语言或闭源 Reader。
6. **建议的后续实验。** 独立附录可做 `static-only`、`18-d probe-only`、`M2 full` 机制消融；并在真实 RPC 或受控网络模拟中记录序列化、压缩、请求/响应头与延迟。它们必须与 C1/C2 主结果分开，不得回填主确认结论。
