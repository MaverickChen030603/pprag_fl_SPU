# V4 完整实验分析

## 1. 总体结论

V4 的实验已经完整完成。与 V3 相比，V4 的确实现了预期中的一个关键机制变化：它不再把上传预算稳定锁定在固定的 `top-k=3`，而是在 harder / more heterogeneous 场景下，通过 `downstream_value + adaptive_v4` 主动把预算提升到 `4` 个块，从而换取更稳或更高的下游结果。

但从最终结果看，V4 的问题也很明确：**它确实更“激进”和更“稳健”，但这种稳健是通过增加上传量换来的。** 换句话说，V4 目前更像是“愿意花更多通信成本来保住下游”，而不是“在相同通信成本下显著优于 V3”。

因此，V4 的最准确定位是：

- 在机制上，成功把 V3 的 value-aware 选择器升级成了更偏 downstream-aware、hard-query/hard-client aware 的预算策略；
- 在结果上，证明了这种策略可以提高预算弹性、在强异构场景下带来更稳的下游指标；
- 但在通信效率上，尚未达到“比 V3 更省、同时还更强”的目标。

## 2. 主结果分析：`v4_main`

`v4_main` 的主结论非常清楚：

| 方法 | payload | MRR | NDCG |
|---|---:|---:|---:|
| `full` | `1.0000` | `0.9200` | `0.9132` |
| `random` | `0.2575` | `0.9089` | `0.9049` |
| `delta_norm` | `0.2316` | `0.8967` | `0.8958` |
| `hypernet_v3` | `0.2266` | `0.8967` | `0.8958` |
| `hypernet_v4` | `0.2822` | `0.9000` | `0.8985` |

这里可以读出三个事实：

1. `hypernet_v4` 的下游指标比 `hypernet_v3` 略高。  
   `MRR` 从 `0.8967` 提升到 `0.9000`，`NDCG` 从 `0.8958` 提升到 `0.8985`。

2. 但这个提升不是“免费”的。  
   `hypernet_v4` 的 payload 从 `0.2266` 上升到 `0.2822`，通信成本明显增加。

3. `random` 在当前主实验中的表现依然很强。  
   它的 `MRR=0.9089`、`NDCG=0.9049`，而 payload 只有 `0.2575`，说明当前任务下参数冗余依然较高。

因此，V4 主结果的含义不是“全面超越”，而是：

**V4 通过增加一定预算，换来了比 V3 更稳的下游指标，但当前还没有在通信效率上击败强随机基线。**

## 3. 预算实验分析：`v4_budget`

预算实验是 V4 最值得看的部分，因为它最能说明“V4 到底把预算花在了哪里”。

### 3.1 低预算区间

在 `k=1` 时：

- `random`: `payload=0.1095`, `MRR=0.9067`, `NDCG=0.8971`
- `delta_norm`: `payload=0.1073`, `MRR=0.9067`, `NDCG=0.8939`
- `hypernet_v3`: `payload=0.1028`, `MRR=0.9067`, `NDCG=0.8939`
- `hypernet_v4`: `payload=0.1596`, `MRR=0.9067`, `NDCG=0.8955`

这说明：

1. V4 在极低预算下没有继续极限压缩，而是主动保留了更多上传量。
2. 它没有显著拉高 `MRR`，只是略高于 `hypernet_v3` 的 `NDCG`。
3. 所以在低预算区间，V4 的策略偏保守，收益并不突出。

### 3.2 中预算区间

在 `k=3` 时：

- `random`: `payload=0.2575`, `MRR=0.9089`, `NDCG=0.9049`
- `delta_norm`: `payload=0.2316`, `MRR=0.8967`, `NDCG=0.8958`
- `hypernet_v3`: `payload=0.2266`, `MRR=0.8967`, `NDCG=0.8958`
- `hypernet_v4`: `payload=0.2822`, `MRR=0.9000`, `NDCG=0.8985`

这里 V4 的模式就很清楚了：

- 比 V3 多花了通信
- 换来了一点下游提升
- 但依然没有在“同预算”意义上压过 `random`

### 3.3 高预算区间

在 `k=5` 时，`hypernet_v4`：

- `payload=0.4025`
- `MRR=0.9100`
- `NDCG=0.9058`

这说明当预算继续放宽时，V4 的下游指标继续向 `full` 靠近。  
所以 V4 是有效的，但更像一条“预算越多、收益越稳”的保守曲线，而不是一条“更省也更强”的高性价比曲线。

**预算实验结论：**

V4 已经证明自己会在 harder setting 下主动用更多预算来保下游，但当前它更擅长“提高鲁棒性”，而不是“以更低预算换更高收益”。

## 4. 异构性实验分析：`v4_heterogeneity`

这是 V4 当前最有亮点的一组。

### 4.1 V3 / `delta_norm` 的行为

在不同 `alpha` 下：

- `delta_norm` 基本稳定在 `payload=0.2316`
- `hypernet_v3` 基本稳定在 `payload≈0.226`

它们的预算行为都很稳定，但也意味着：

- 它们对 harder heterogeneity 的响应并不明显
- 更像“固定压缩率”的方法

### 4.2 V4 的行为

V4 在不同异构强度下：

- `alpha=0.5`: `payload≈0.2819`
- `alpha=0.3`: `payload≈0.2822`
- `alpha=0.1`: `payload≈0.2817`
- `alpha=0.05`: `payload≈0.2826`

而且实时日志清楚表明，在 `alpha=0.1 / 0.05` 这类更强异构场景中，`avg_budget_topk` 会稳定提高到 `4.00`。

这代表了 V4 相比 V3 最核心的机制差异：

- V3：更像一个稳定固定预算选择器
- V4：已经开始对 harder setting 做真正的预算扩张

### 4.3 这种扩张换来了什么

看下游：

- `alpha=0.1` 下，`hypernet_v4` 的 `MRR=0.9167`, `NDCG=0.9107`
- 同场景下，`hypernet_v3` 的 `MRR=0.9100`, `NDCG=0.9058`
- `alpha=0.05` 下，`hypernet_v4` 与 `delta_norm` 一样都达到 `MRR=0.9200`, `NDCG=0.9194`

所以异构性实验说明：

1. V4 的预算扩张不是无意义的；
2. 它确实换来了更好的 harder-scene 下游保持；
3. 但它的代价就是 payload 上升了约 `0.05~0.06`。

**异构性实验结论：**

V4 在强异构场景下的优势是真实存在的，但目前这个优势是“用更多预算买来的稳健性提升”。

## 5. Hard Query 实验分析：`v4_hardquery`

`v4_hardquery` 的对比也支持同样的结论：

- `hypernet_v3`: `payload=0.2268`, `MRR=0.8967`, `NDCG=0.8958`
- `hypernet_v4`: `payload=0.2822`, `MRR=0.9000`, `NDCG=0.8985`

也就是说：

- V4 的下游确实略强
- 但它仍然是通过增加预算获得的

因此，hardquery 套件进一步验证：

**V4 比 V3 更保守，也更稳；但目前还没有达到“更聪明地花同样预算”的阶段。**

## 6. Signal 消融分析：`v4_ablation_signal`

分组统计结果是：

- `payload = 0.2821 ± 0.0018`
- `MRR = 0.9000`
- `NDCG = 0.8985`

而且从全量报告片段看：

- `downstream_value`
- `value`
- `hard flag on/off`
- `utility flag on/off`

在当前实验里造成的差异很小。

这意味着：

1. 当前 V4 的多数收益，不一定来自更精细的 downstream signal 本身；
2. 更大的变化，可能主要来自 **`adaptive_v4` 整体把预算抬高**。

所以 V4 当前版本虽然“看起来更聪明”，但实验上最直接有效的部分，可能还是：

**更激进的预算扩张，而不是更精细的 signal 学习。**

## 7. Budget 消融分析：`v4_ablation_budget`

预算消融分组统计：

- `payload = 0.2452 ± 0.0263`
- `MRR = 0.8978`
- `NDCG = 0.8967`

这说明预算模式本身确实带来了可观察差异。  
从报告片段可读出：

- `fixed` / 普通 `adaptive` 更接近 `V3` 行为
- `adaptive_v4` 会明显提高 payload
- 这会把下游指标略微往上推

因此，预算消融的核心结论是：

**V4 当前最“有效”的模块，不是 signal 复杂化，而是预算机制本身。**

## 8. Explain 实验分析：`v4_explain`

`v4_explain` 的结果：

- `payload = 0.3733`
- `recall_3 = 0.9400 ± 0.0047`
- `MRR = 0.9067`
- `NDCG = 0.9006 ± 0.0036`

Explain 套件主要说明：

1. 当解释性统计链打开并保持更重的上传行为时，V4 的下游指标依然稳定；
2. explain 模块没有破坏主流程；
3. 后续可以继续利用 explain 文件去分析：
   - 哪些 block 被更频繁选中
   - 哪些 harder client 得到更多预算
   - budget uplift 是否和 downstream proxy 一致

## 9. 对 V4 的最终评价

### 9.1 V4 成功的地方

V4 已经成功做到三件事：

1. **把 V3 的稳定固定预算，升级成了真正会根据 harder setting 扩张预算的机制。**
2. **在强异构和 harder query 场景下，的确换来了更稳或略高的下游指标。**
3. **整套 downstream-aware + adaptive_v4 + 自动化收尾链已经工程化跑通。**

### 9.2 V4 还不够理想的地方

V4 最大的问题也很明确：

1. `payload` 普遍高于 V3；
2. 下游收益提升幅度偏小；
3. 在“同通信预算下更优”这件事上，证据还不够强；
4. 当前 strongest gain 更像“用更多通信换更稳结果”，而不是“更聪明地花同样的通信”。

### 9.3 最终一句话结论

**V4 成功证明了 downstream-aware + adaptive_v4 能让方法在 harder setting 下更主动地保下游效果，但它当前仍然更像“稳健性增强版 V3”，而不是“通信效率全面超越版 V3”。**

## 10. 下一步最值得做什么

如果继续做 V5 / 下一阶段，我会优先做：

1. **同预算严格对齐实验**  
   重新把 V3 / V4 调到相近 payload 区间，只比下游。

2. **降低 V4 的预算膨胀**  
   让 `adaptive_v4` 只在真正 hard client / hard query 上扩张，而不是较大范围抬高平均 payload。

3. **增强 downstream utility proxy 的判别力**  
   让 V4 的 signal 真正能区分“哪些块值得多花通信”。

4. **把 explain 结果做成 block-level / client-level 对照图**  
   进一步证明预算扩张不是随机行为，而是和 harder setting 有结构性对应。
